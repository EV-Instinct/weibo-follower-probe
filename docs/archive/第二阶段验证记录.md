## A 的真实 Edge 自动读取

- A 最初由未启用调试端口的 Edge 占用。用户关闭 A 专用窗口后，Playwright 用同一个档案重新打开 Edge，保留了登录状态。运行中实测了档案占用提示。其他 Edge 窗口与档案未关闭。
- 通过顶部导航的个人头像链接识别登录 UID，点击后核对自己的主页 URL。从实测的「我的粉丝」入口进入，核对列表页 URL 中的目标 UID 和 `relate=fans`，轮末再核对登录 UID。粉丝链接限定在「全部粉丝」面板的粉丝行内，每行读取头像对应的资料链接，排除行内来源链接和外部区域。
- 正式命令首次成功读到两条不同的真实 UID，标题计数为 2，第一条与截图相符。随后两次复读仍是相同的两条，顺序一致，无重复或未解析链接。保存文件只有一轮标为历史基线。每轮的开始和结束时间、归属、去重数、显示范围及结束原因均已落盘。文件不保存原始 URL、凭据、会话内容或页面截图。
- 正常进入时曾显示「粉丝数倒序」。用菜单切到「关注时间倒序」后，DOM 会分阶段加载。早期几轮因此记录为 `load-failed`，没有进入样本。现在等待所选排序生效、粉丝行出现及末尾提示加载。实测显示部分账号暂不展示，行内未观察到具体关注时间。A 只验收了一个已渲染窗口，正式命令以 `no-proven-continuation` 结束，全量保持未验证。
- 单独滚动至当前列表提示，前后均为同样两条记录，没有追加，未发现下一页控件。该结果仅覆盖 A 当前的短列表。打开顶部消息入口后实测有「@我的」「评论」「赞」和「私信」，当前消息界面及顶部菜单未发现「新粉丝」或「关注通知」分类。这个检查不涉及客户端或未触发的新关注通知。
- `npm.cmd run read:a` 为正式入口。证据位于 `%LOCALAPPDATA%\WeiboFollowerProbe\weibo-a-observations.json`。真实登录失效、重新登录、受控新增、重新关注、更多窗口和列表上限尚未完成验收。`npm.cmd test` 通过全部 11 项本地测试。

使用本机 Microsoft Edge `156.0.4314.58`、Playwright Core `1.65.0`、Node.js `24.14.1`。浏览器测试只访问环回页面，所有账户、关系数据和操作均为模拟。

| 证据 | 结果 |
| --- | --- |
| Edge 持久档案 A/B | 由账号菜单识别不同 UID，拒绝错误的目标 UID。关闭重开模拟 A 后仍能识别。模拟退出 A 后只影响 A，重新登录恢复读取。 |
| 页面读取与去重 | 从账号菜单点击进入模拟主页，再进粉丝区域。排除区域外的推荐和关注列表链接。两段共出现 3 次 UID，去重 2 个。复读得到相同样本，另一个用例读到颠倒顺序。 |
| 翻页、动态追加和异常 | 分别验证了界面翻页、点击后向当前 DOM 追加、列表加载失败和无进展。单元测试覆盖窗口预算、身份切换、归属冲突、访问拦截以及不可解析链接。 |
| 保存与范围 | 模拟证据写入临时 JSON 后读回核对。逐段保存规范化 UID，保存轮次时间、账号、范围、精确总数和结束原因。采集不到可靠身份时 UID 列表为空。日志和证据无会话凭据、页面转储、原始链接查询参数或 Playwright 原始错误详情。 |
| 单账号正式入口补测 | 用 Edge 操作 `probe.mjs` 的本地表单，在隔离目录提交 A 的两条模拟粉丝链接并原样复读。首轮和复读均成功落盘，界面分别标明初始样本与复读，同一份样本没有产生新候选。不同所有者提交被拒绝。摘要没有输出真实数据或模拟 UID，原有服务和数据未受影响。 |

## 新增所需证据

1. 首轮样本是历史观测。对后续首见 UID，仅记录发现时刻。发现时刻是软件读到的时间，注册时间是粉丝账号创建的时间，关注时间是该 UID 对目标账号建立关注关系的时间。
2. 要确认监测开始后新增，至少要核对目标账号和粉丝两个 UID，并取得可核实的关系证据。例如平台逐条提供语义明确的关注时间或可归属的关注事件，或者由平台提供覆盖完整且能比较的前后关系快照。当前没有真实页面证据证明任一条件成立。通知如果只提供数量、昵称、聚合提醒或不明时间，仍需额外证据。
3. 新增事件与首次累计 UID 分开处理。受控取关后再关注可能产生新的关系事件，但已累计的 UID 在同一目标账号下只能计一次。对可能曾是历史粉丝且基线不完整的首见 UID，保留待确认。自动确认、每 60 条导出和 50 账号轮询待真实证据通过后推进。

## 真实账号验收顺序

1. A 的自动识别、可见窗口的基线与复读已完成。更多窗口需要使用实际有更多可见粉丝的样本单独验证。
2. 受控关注、取关、重新关注等用户准备好执行操作的账号后另行验证。重点核对操作后是否出现逐条提醒，能否从中关联粉丝 UID 与时间。
3. 由用户在 A 的站内菜单主动退出，再手动重登原账号并核对历史归属。自然到期和双账号隔离另行核验。
4. 如果获得真实站点自动读取许可，按获准页面和频率开展 Playwright 验证。需要复用已占用的 A 或 B 档案时，先由用户关闭对应的专用 Edge 窗口，再核查专用进程是否退出。档案保留，其他浏览器继续使用。
