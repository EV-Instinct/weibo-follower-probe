# 历史说明：早期手动取样与诊断工具

> 本文档归档自早期原型阶段的手动取样与验证脚本说明，供历史参考。正式应用请参见 [使用说明](../../使用说明.md) 与 [README](../../README.md)。

## A 账号真实读取

在装有 Microsoft Edge 和 Node.js 24 的 Windows 上，在项目目录运行：

```powershell
npm.cmd ci
npm.cmd run read:a
```

如果 A 的独立 Edge 窗口仍开着，先关闭该窗口。命令使用 `%LOCALAPPDATA%\WeiboFollowerProbe\profiles\A` 中的既有档案。若命令提示登录，在打开的微博窗口里自行登录，完成后回到命令行按 Enter。

命令通过顶部头像和自己的主页交叉核对 UID，从「我的粉丝」进入同一账号的粉丝区，选用「关注时间倒序」，连续滚动读取已渲染的粉丝卡片。观测保存在 `%LOCALAPPDATA%\WeiboFollowerProbe\weibo-a-observations.json`。

## 手动取样工具

Windows 上使用 Microsoft Edge 和 Node.js 24。双击 `启动验证.cmd` 或在工作区运行 `node probe.mjs`，然后访问 `http://127.0.0.1:8765/`。

如果本地页的 A 按钮打不开浏览器，可以在文件资源管理器里双击 `打开账号A.cmd`。它使用相同的 A 档案。

1. 在验证页点「打开账号 A」。在官方页面自行登录。点自己的头像进入主页，复制主页链接，随后从自己的主页进入「粉丝」。将主页链接和按可见顺序手动复制的粉丝资料链接填到本地页。
2. B 同理。首次记录 B 的独立基线，再对 A 原样复读一次。
3. 先在 B 查看是否已经关注 A。由 B（或另一个受控账号）在平台正常操作一次关注 A。在 A 中记录同一范围并查看是否有带 UID 与时间的新粉丝提醒。
4. 最后仅在 A 官方页面主动退出。重新打开确认是否要求登录，并在验证工具登记「要求重新登录」。
