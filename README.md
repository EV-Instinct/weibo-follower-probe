# 微博粉丝助手 0.3.0

一个查看账号登录，通过目标 UID 监控多个公开博主的粉丝列表顶部。首次建立底册，后续按有序快照推断关注事件，包含观察到的重新关注，每目标满 60 条导出。

## 启动与构建

双击“启动新版微博粉丝助手.exe”；保留 dist/微博粉丝助手_0.3.0。开发使用 npm start，构建使用 npm run build。原生 C# 启动器校验版本、数据目录和数据库身份，重复点击复用后台。打包需要 .NET Framework C# 编译器，用户运行不需要安装 Node。

## 实现

- watch-app.mjs：仅监听环回地址的 HTTP API，校验 Host、Origin 和 CSRF。
- watch-store.mjs：独立 watch.sqlite，保存目标顶部快照、关注事件和导出批次。UID 不是事件唯一键；预留批次与事件绑定在事务中完成，文件生成可恢复。
- watch-service.mjs：共用查看账号，串行检查，处理登录失效与平台限制。
- watch-browser.mjs：普通页面导航和滚动，提取约 120 个顶部 UID，核对查看账号、目标身份和连续行号；仅被动观察浏览器自然请求的总数和结束标记。
- ui/watch.*：一个查看账号、多目标 UID 的管理界面。
- monitor-* 等旧模块保留用于复用与旧模式回归，旧数据库不改成新事件。

初次导入原账号 A（或第一个已绑定账号）的独立登录档案及导出目录。原账号不会自动作为监控目标。比较算法用已知 UID 的最长递增序列定位稳定后缀；新前缀作为关注事件，旧 UID 重新进入前缀也可计数。锚点不足或后缀相对顺序异常时保留底册并报告缺口。

## 验证

npm test 覆盖旧版回归和新模式存储、重新关注、导出恢复、串行调度、目标页面读取、浏览器 UI。node portable-smoke.mjs 验证自带运行时；node launcher-smoke.mjs 验证 EXE 重复启动与重启持久化。

所有模拟测试只使用临时数据目录，不使用真实登录档案进行网络模拟，不向生产粉丝库写入模拟数据。用户已取消热门账号增长实验，本次验收仅执行隔离的实现测试与本地启动检查。

环境变量：WEIBO_MONITOR_DATA_DIR、WEIBO_MONITOR_PORT、WEIBO_MONITOR_EXPORT_DIR。默认端口 127.0.0.1:8766。

## 边界

顶部顺序变化是推断，不是平台官方关注事件流。不可见关注、超过窗口的变化，以及没有留下顺序变化的重新关注无法完整识别；过滤、恢复展示或排序变化可能误判。详细操作见使用说明.md。
